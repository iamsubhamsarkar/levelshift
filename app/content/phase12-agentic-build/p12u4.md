## BUILD_STEP
goal: Add a "dangerous" tool that must never run unsupervised.
why: For irreversible or expensive actions, the agent should PROPOSE, and a human should APPROVE. We add a tool worth gating. (Learned in Phase 9, Ch 16, section 16.6.)
code:
```
def delete_file(path: str) -> dict:
    """Delete a file. DANGEROUS — irreversible."""
    import os
    os.remove(path)
    return {"deleted": path}

TOOL_IMPLS["delete_file"] = delete_file
DANGEROUS_TOOLS = {"delete_file"}
```
verify: The file saves. delete_file is registered and marked dangerous. It is exactly the kind of irreversible action that needs a human gate.
reference: Phase 9, Ch 16

## BUILD_STEP
goal: Intercept dangerous tool calls and PAUSE for approval.
why: The pattern: the agent proposes an action; the system pauses and shows it to a human with context; the human approves, edits, or rejects. (Learned in Phase 9, Ch 16, section 16.6.)
code:
```
def run_tool_call_gated(tool_call):
    name = tool_call.function.name
    args = tool_call.function.arguments
    if name in DANGEROUS_TOOLS:
        print(f"\n[APPROVAL NEEDED] ATLAS wants to run {name} with {args}")
        choice = input("Approve? (y/n): ").strip().lower()
        if choice != "y":
            return {"error": "action rejected by human"}
    return run_tool_call(tool_call)   # your validated dispatcher from Phase 10
```
verify: When ATLAS requests delete_file, execution PAUSES and asks you to approve. Only on "y" does it proceed; on anything else it returns a rejection observation the agent can react to.
troubleshoot: If the pause never appears, confirm the loop calls run_tool_call_gated (not the un-gated dispatcher) for tool execution.
reference: Phase 9, Ch 16

## BUILD_STEP
goal: Place the gate at the FEW high-stakes points only.
why: Over-gating buries the user in prompts; under-gating is dangerous. Deciding WHERE the gates go is the real design work. (Learned in Phase 9, Ch 16, section 16.6.)
code:
```
# Keep DANGEROUS_TOOLS small — only truly irreversible/expensive actions:
#   delete data, send money, email customers, change production.
# Safe, read-only tools (search_docs, get_word_count) must NOT be gated,
# or the tool becomes annoying and users abandon it.
```
verify: Only genuinely dangerous tools are in DANGEROUS_TOOLS. Read-only and harmless tools run without interruption; the gate appears only where the stakes are real.
reference: Phase 9, Ch 16
