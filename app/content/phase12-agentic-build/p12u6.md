## BUILD_STEP
goal: Retry only TRANSIENT failures with growing backoff.
why: Retry timeouts, 429 rate limits, and 5xx errors with a growing wait — but never retry a 401 or 400, which will never succeed. (Learned in Phase 9, Ch 17, section 17.5, and Ch 3.)
code:
```
import time

TRANSIENT = (429, 500, 502, 503, 504)

def call_with_retry(make_call, retries=3):
    for attempt in range(retries):
        try:
            return make_call()
        except Exception as e:
            status = getattr(e, "status_code", None)
            transient = status in TRANSIENT or "timeout" in str(e).lower()
            if not transient or attempt == retries - 1:
                raise                      # don't retry 401/400 or the last attempt
            wait = 2 ** attempt            # 1s, 2s, 4s
            print(f"[retry] transient {e} — waiting {wait}s")
            time.sleep(wait)
```
verify: A simulated 429 triggers backoff-and-retry; a simulated 401 (bad key) fails immediately without wasting retries. Only transient errors are retried.
reference: Phase 9, Ch 17

## BUILD_STEP
goal: Add a provider FALLBACK — if Groq fails, switch to NVIDIA NIM.
why: Because you coded against the common interface (Chapter 3), failing over from one provider to another is straightforward — the payoff of provider-agnosticism. (Learned in Phase 9, Ch 17, section 17.5.)
code:
```
primary = OpenAI(api_key=os.environ["GROQ_API_KEY"],
                 base_url=os.environ["GROQ_BASE_URL"], timeout=30)
backup = OpenAI(api_key=os.environ.get("NIM_API_KEY", ""),
                base_url=os.environ.get("NIM_BASE_URL", ""), timeout=30)

def robust_chat(messages, **kw):
    try:
        return call_with_retry(lambda: primary.chat.completions.create(
            model=os.environ["GROQ_MODEL"], messages=messages, **kw))
    except Exception as e:
        print(f"[fallback] primary failed ({e}); switching to NIM")
        return backup.chat.completions.create(
            model=os.environ.get("NIM_MODEL", ""), messages=messages, **kw)
```
verify: If the primary provider is unreachable or exhausted, ATLAS transparently switches to the backup and still answers. On a healthy primary, the backup is never touched.
troubleshoot: Fill in NIM credentials in .env for a real fallback. If you have only one provider, a smaller model, a cached answer, or a safe canned reply are valid fallbacks too.
reference: Phase 9, Ch 17

## BUILD_STEP
goal: Make dangerous actions idempotent (safe to retry).
why: Since a request may be retried, a retried "delete" or "send payment" must not happen twice — use an idempotency key. (Learned in Phase 9, Ch 17, section 17.5.)
code:
```
DONE_ACTIONS = set()   # in production: a persistent store

def idempotent(action_key, do_it):
    if action_key in DONE_ACTIONS:
        return {"status": "already done", "key": action_key}
    result = do_it()
    DONE_ACTIONS.add(action_key)
    return result
# Wrap consequential tools so a retry with the same key does not repeat the effect.
```
verify: Calling a consequential action twice with the same key performs it only once — the second call reports "already done." Retries are now safe.
reference: Phase 9, Ch 17
