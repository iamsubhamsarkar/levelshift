## BUILD_STEP
goal: Write a tiny MCP SERVER that exposes one tool. Create mcp_server.py.
why: A server EXPOSES capabilities over the standard protocol. This wraps your word-count logic so it is reusable across any MCP host. (Learned in Phase 9, Ch 13, section 13.3.)
code:
```
# mcp_server.py — an MCP server exposing one tool (illustrative; adapt to SDK version)
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("atlas-tools")

@mcp.tool()
def get_word_count(text: str) -> dict:
    """Count the words in a piece of text."""
    return {"word_count": len(text.split())}

if __name__ == "__main__":
    mcp.run()
```
windows:
```
python mcp_server.py
```
ubuntu:
```
python3 mcp_server.py
```
verify: The server starts and waits, announcing it offers a get_word_count tool. This same server could be consumed by ANY MCP host — your agent, a coding assistant, a chat app.
troubleshoot: If FastMCP's import path differs, consult the SDK's current quickstart. The concept — a server publishes tools with described inputs — is stable.
reference: Phase 9, Ch 13

## BUILD_STEP
goal: Apply MCP security — trust and least privilege.
why: MCP does not remove Chapter 6's safety work — it EXPANDS it, because capabilities can now come from parties you did not write. (Learned in Phase 9, Ch 13, section 13.6.)
code:
```
# Security checklist for any MCP server you connect:
#  - TRUST: only connect to servers you wrote or have reviewed (supply-chain risk).
#  - UNTRUSTED TEXT: treat tool descriptions AND results as untrusted — a malicious
#    server can hide instructions in them (indirect prompt injection, Ch 16).
#  - LEAST PRIVILEGE: give each server the narrowest access it needs.
#  - AUTH: never expose a network-reachable server with powerful tools unprotected.
```
verify: You can state, for your own server, why it is safe to trust (you wrote it), and you understand that a third-party server's descriptions and results must be treated as untrusted input.
reference: Phase 9, Ch 13, Ch 16
