## BUILD_STEP
goal: Give ATLAS a session that remembers the conversation across turns.
why: The model is stateless — memory is an illusion YOU create by re-sending history. A small session object holds it outside the model. (Learned in Phase 9, Ch 2 and Ch 9.)
code:
```
class Session:
    def __init__(self, system_prompt):
        self.messages = [{"role": "system", "content": system_prompt}]

    def user(self, text):
        self.messages.append({"role": "user", "content": text})

    def assistant(self, text):
        self.messages.append({"role": "assistant", "content": text})

session = Session("You are ATLAS, a concise assistant.")
```
verify: The file saves. The session's messages list IS the conversation — the entire memory, carried on every call.
reference: Phase 9, Ch 9

## BUILD_STEP
goal: Add truncation (a sliding window) to keep the conversation from overflowing.
why: Long conversations overflow the finite context "desk" and cost more each turn. Truncation is the simplest fix — keep the system prompt plus the most recent messages. (Learned in Phase 9, Ch 9, section 9.3.)
code:
```
def trimmed(messages, keep_recent=6):
    system = messages[0:1]              # always keep the system prompt
    recent = messages[1:][-keep_recent:]  # keep only the last N turns
    return system + recent
# Use ask(trimmed(session.messages)) for very long chats.
```
verify: On a long conversation, only the system prompt plus the last few turns are sent. Confirm by printing len(trimmed(session.messages)) — it stays bounded no matter how long the chat grows.
troubleshoot: Truncation risks forgetting an important EARLY fact. If early context matters, prefer summarization (next step) over dropping messages.
reference: Phase 9, Ch 9

## BUILD_STEP
goal: Add summarization — compress old turns into a short summary instead of dropping them.
why: Summarization preserves the gist of early messages while using far fewer tokens — the standard 2026 technique for long-running agents. (Learned in Phase 9, Ch 9, section 9.3.)
code:
```
def summarize_old(messages, keep_recent=4):
    system = messages[0]
    old = messages[1:-keep_recent]
    recent = messages[-keep_recent:]
    if len(old) < 2:
        return messages
    summary = ask([
        {"role": "system", "content": "Summarize this conversation so far in 2-3 sentences, keeping key facts."},
        {"role": "user", "content": str(old)},
    ])
    return [system, {"role": "system", "content": f"Summary so far: {summary}"}] + recent
```
windows:
```
python atlas.py
```
ubuntu:
```
python3 atlas.py
```
verify: After many turns, the old messages collapse into one short "Summary so far:" line, and ATLAS still recalls key facts (like "Java") from the summary rather than the raw transcript.
troubleshoot: If the summary drops a detail that later matters, tighten the summarizer prompt ("keep names, preferences, and decisions"). Summarize WITH the goal in mind.
reference: Phase 9, Ch 9

## BUILD_STEP
goal: Add a tiny profile (key-value) memory that persists across runs.
why: Not every memory needs machinery — a small store of facts, loaded into the system prompt each run, covers a lot. (Learned in Phase 9, Ch 9, section 9.4.)
code:
```
import json, os

def load_profile(path="profile.json"):
    return json.load(open(path)) if os.path.exists(path) else {}

def save_profile(profile, path="profile.json"):
    json.dump(profile, open(path, "w"))

profile = load_profile()
profile["favorite_language"] = "Java"
save_profile(profile)
```
