## BUILD_STEP
goal: Force valid JSON at the provider level (Level 2). Update ask() to accept a json_mode flag.
why: Most OpenAI-compatible providers can GUARANTEE syntactically valid JSON, removing stray prose and broken syntax. This is Level 2. (Learned in Phase 9, Ch 5, section 5.3.)
code:
```
def ask(messages, temperature=0, json_mode=False):
    kwargs = {"model": MODEL, "messages": messages, "temperature": temperature}
    if json_mode:
        kwargs["response_format"] = {"type": "json_object"}
    response = client.chat.completions.create(**kwargs)
    return response.choices[0].message.content
```
verify: The file saves. Calling ask(..., json_mode=True) will now return only valid JSON text — no prose, no fences.
troubleshoot: If your provider rejects response_format, it may not support JSON mode for that model. Fall back to a strong Level-1 prompt ("reply with ONLY JSON") and rely on the Level-3 validation in the next step to catch problems.
reference: Phase 9, Ch 5

## BUILD_STEP
goal: Add a schema and a validating classify() to atlas.py.
why: Now the output is BOTH valid JSON AND the exact structure you require. Anything malformed is rejected, not silently trusted. (Learned in Phase 9, Ch 5.)
code:
```
from pydantic import BaseModel, field_validator

ALLOWED = {"BLOCKER", "MAJOR", "MINOR", "TRIVIAL"}

class Triage(BaseModel):
    severity: str
    component: str

    @field_validator("severity")
    @classmethod
    def known_severity(cls, v):
        if v not in ALLOWED:
            raise ValueError(f"severity must be one of {ALLOWED}")
        return v

def classify(text):
    raw = ask([
        {"role": "system", "content":
         "Classify severity as one of BLOCKER, MAJOR, MINOR, TRIVIAL and name the component. "
         "Reply with ONLY a JSON object with keys 'severity' and 'component'."},
        {"role": "user", "content": text},
    ], json_mode=True)
    return Triage.model_validate_json(raw)

print(classify("Users cannot log in at all since this morning."))
```

```

```
verify: You get a validated Triage object, e.g. severity='BLOCKER' component='login'. If the model returned a bad severity, pydantic raises a clear ValidationError instead of letting garbage through.

## BUILD_STEP
goal: Add self-correction — feed a validation error back to the model and retry.
why: A fallible generator wrapped in a checking loop is the deepest recurring shape in agentic engineering. This previews reflection (Ch 7). (Learned in Phase 9, Ch 5, section 5.4.)
code:
```
def classify_safe(text, max_retries=2):
    messages = [
        {"role": "system", "content":
         "Classify severity as one of BLOCKER, MAJOR, MINOR, TRIVIAL and name the component. "
         "Reply with ONLY a JSON object with keys 'severity' and 'component'."},
        {"role": "user", "content": text},
    ]
    for attempt in range(max_retries + 1):
        raw = ask(messages, json_mode=True)
        try:
            return Triage.model_validate_json(raw)
        except Exception as e:
            if attempt == max_retries:
                raise
            messages.append({"role": "assistant", "content": raw})
            messages.append({"role": "user",
                             "content": f"That failed validation: {e}. Please correct it."})
```
windows:
```
python atlas.py
```
ubuntu:
```
python3 atlas.py
```
verify: classify_safe() returns a valid Triage even if the first attempt was malformed — you can see it recover by printing each attempt. On a well-behaved model it succeeds on the first try.
reference: Phase 9, Ch 5
