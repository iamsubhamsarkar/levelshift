## BUILD_STEP
goal: Write a real tool as an ordinary Python function. Add it to atlas.py.
why: A tool is just reliable code the model can request. We give it ONE clear purpose and validated inputs. (Learned in Phase 9, Ch 6, section 6.5.)
code:
```
def get_word_count(text: str) -> dict:
    """Count the words in a piece of text."""
    if not isinstance(text, str):
        return {"error": "text must be a string"}
    return {"word_count": len(text.split())}
```
verify: The file saves. This is your first tool — plain, testable code with one job and an informative failure path.
reference: Phase 9, Ch 6

## BUILD_STEP
goal: Describe the tool to the model in the OpenAI tool-calling schema.
why: The DESCRIPTION is the real interface — the model decides whether and how to use the tool almost entirely from it. Write it like docs for a new teammate. (Learned in Phase 9, Ch 6, section 6.2.)
code:
```
TOOLS = [{
    "type": "function",
    "function": {
        "name": "get_word_count",
        "description": "Count the number of words in a given piece of text. "
                       "Use this whenever the user asks how many words something has.",
        "parameters": {
            "type": "object",
            "properties": {
                "text": {"type": "string", "description": "The text to count words in."}
            },
            "required": ["text"],
        },
    },
}]
```
verify: The file saves. Notice how the description says WHAT it does and WHEN to use it — that clarity is what drives good tool selection.
reference: Phase 9, Ch 6

## BUILD_STEP
goal: Send the tools with your request and detect a tool-call request.
why: The model does not run your code — it REQUESTS that you run it, via a tool_calls finish reason. (Learned in Phase 9, Ch 6, section 6.1.)
code:
```
def call_with_tools(messages):
    return client.chat.completions.create(
        model=MODEL, messages=messages, tools=TOOLS, temperature=0,
    )

messages = [
    {"role": "system", "content": "You are ATLAS. Use tools when they help; do not guess."},
    {"role": "user", "content": "How many words are in: the quick brown fox jumps?"},
]
resp = call_with_tools(messages)
msg = resp.choices[0].message
print("wants tool?", bool(msg.tool_calls))
```
windows:
```
python atlas.py
```
ubuntu:
```
python3 atlas.py
```
verify: It prints "wants tool? True" — the model responded with a request to run get_word_count, not a final answer.
troubleshoot: If it prints False, your tool description may be unclear, or the question did not obviously need the tool. Make the description sharper and the question more direct.
reference: Phase 9, Ch 6

## BUILD_STEP
goal: Execute the requested tool and validate its arguments before running.
why: The arguments the model supplies are UNTRUSTED — validate them exactly like input to a REST endpoint. (Learned in Phase 9, Ch 6, section 6.4.)
code:
```
import json

TOOL_IMPLS = {"get_word_count": get_word_count}

def run_tool_call(tool_call):
    name = tool_call.function.name
    args = json.loads(tool_call.function.arguments)  # untrusted!
    fn = TOOL_IMPLS.get(name)
    if fn is None:
        return {"error": f"unknown tool {name}"}
    return fn(**args)
```
verify: The file saves. This dispatcher looks up the real function and passes the model's arguments — which the function itself validates.
reference: Phase 9, Ch 6

## BUILD_STEP
goal: Complete the four-step cycle by hand — request, result, then answer.
why: This is the atom of tool use: user, assistant tool-request, tool result, assistant final answer. (Learned in Phase 9, Ch 6, section 6.3.)
code:
```
if msg.tool_calls:
    messages.append(msg)  # keep the model's request in the conversation
    for tc in msg.tool_calls:
        result = run_tool_call(tc)
        messages.append({
            "role": "tool",
            "tool_call_id": tc.id,
            "content": json.dumps(result),
        })
    final = client.chat.completions.create(model=MODEL, messages=messages, temperature=0)
    print(final.choices[0].message.content)
```
windows:
```
python atlas.py
```
ubuntu:
```
python3 atlas.py
```
verify: The final answer states the correct word count (6), computed by your real code — not guessed by the model. You have wired one full tool cycle by hand.
troubleshoot: If the model's request is dropped from the conversation (the messages.append(msg) line), the follow-up call will fail to connect the tool result to the request. Keep that line.
reference: Phase 9, Ch 6
