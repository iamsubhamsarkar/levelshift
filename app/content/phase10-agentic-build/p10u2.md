## BUILD_STEP
goal: Load your API key and build one OpenAI-compatible client. Paste this into atlas.py.
why: One client, built from environment variables, can talk to Groq OR NVIDIA NIM — because both speak the OpenAI-compatible protocol. This is dependency injection applied to LLM providers. (Learned in Phase 9, Ch 3.)
code:
```
import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()  # reads your .env file

client = OpenAI(
    api_key=os.environ["GROQ_API_KEY"],
    base_url=os.environ["GROQ_BASE_URL"],
)
MODEL = os.environ["GROQ_MODEL"]
```
verify: The file saves without error. Nothing runs yet — the next step makes the actual call.
troubleshoot: If you later see a KeyError, your .env is missing that exact key name. Re-open .env and confirm GROQ_API_KEY, GROQ_BASE_URL, and GROQ_MODEL are all present and spelled correctly.
reference: Phase 9, Ch 3

## BUILD_STEP
goal: Make your first LLM call. Add this to the bottom of atlas.py, then run it.
why: This is the messages-and-roles structure from the theory, made real: a system message sets the job, a user message asks the question. (Learned in Phase 9, Ch 3.)
code:
```
response = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "system", "content": "You are a concise, accurate assistant."},
        {"role": "user", "content": "In one sentence, what is an AI agent?"},
    ],
    temperature=0,
)
print(response.choices[0].message.content)
```
windows:
```
python atlas.py
```
ubuntu:
```
python3 atlas.py
```
verify: The terminal prints a one-sentence definition of an AI agent. You just completed a real, stateless LLM call — a request in, a reply out.
troubleshoot: A 401 means a bad API key. A 404 or "model not found" means the model name in .env has been retired — copy a current one from your provider's model list. A "too many requests" (429) means you hit the free-tier rate limit; wait a minute and retry.
reference: Phase 9, Ch 3

## BUILD_STEP
goal: Wrap the call in a reusable function called ask(). Replace the loose call code with this.
why: A tiny function gives you ONE place to change the model, temperature, or provider later — the seed of a provider-agnostic client. (Learned in Phase 9, Ch 3 and Ch 12.)
code:
```
def ask(messages, temperature=0):
    response = client.chat.completions.create(
        model=MODEL,
        messages=messages,
        temperature=temperature,
    )
    return response.choices[0].message.content

if __name__ == "__main__":
    reply = ask([
        {"role": "system", "content": "You are a concise, accurate assistant."},
        {"role": "user", "content": "In one sentence, what is an AI agent?"},
    ])
    print(reply)
```
windows:
```
python atlas.py
```
ubuntu:
```
python3 atlas.py
```
verify: Running atlas.py still prints the one-sentence answer — but now the call lives behind a clean ask() function you will reuse in every later step.
reference: Phase 9, Ch 3

## BUILD_STEP
goal: Prove provider-agnosticism — swap to NVIDIA NIM without touching your logic (optional but recommended).
why: Because you coded against the common interface, switching providers is a config change, not a rewrite. This is the payoff of the OpenAI-compatible standard. (Learned in Phase 9, Ch 3, section 3.5.)
code:
```
# In .env, add NIM credentials, then point the three vars at them:
# NIM_API_KEY=nvapi-...
# NIM_BASE_URL=https://integrate.api.nvidia.com/v1
# NIM_MODEL=meta/llama-3.3-70b-instruct
#
# To switch, change only these three lines in atlas.py:
# api_key=os.environ["NIM_API_KEY"]
# base_url=os.environ["NIM_BASE_URL"]
# MODEL = os.environ["NIM_MODEL"]
```
verify: With only the key, base URL, and model name changed, atlas.py runs against NIM and prints an answer — your ask() function and all other code are untouched.
troubleshoot: If NIM rejects the model name, copy a current model id from build.nvidia.com. If you prefer to stay on Groq, skip this step — the rest of the build works identically on either provider.
reference: Phase 9, Ch 3
